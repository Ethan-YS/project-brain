## 6. 工作流清单（v2.1，仅多工作流项目填）

> **本节只在多工作流项目里填** —— 单工作流项目这一节可保留为空或删除。
> 工作流之间共享 PROJECT / MAP / DECISIONS / topics；分裂 STATUS / HANDOFF / handoffs。
> 详见 METHODOLOGY §3.5（几个窗口同时开着的，再看 §3.6）。

| 工作流 | 管哪些（它改的目录 / 范围） | STATUS 文件 | HANDOFF 文件 | 归档目录 |
|---|---|---|---|---|
| ⚠️ TODO ⚠️ | ⚠️ TODO ⚠️ | `STATUS_⚠️.md` | `HANDOFF_⚠️.md` | `handoffs/⚠️/` |

不归自己管的范围不动手改，写清楚交给管它的那条工作流（METHODOLOGY §3.6.3）。

**新增工作流的协议**：
1. 用户拍板新工作流名（保持和现有命名风格一致 —— 全英文或都用所选语言）
2. AI 创建 `STATUS_<新工作流>.md` + `HANDOFF_<新工作流>.md`（用模板）+ `handoffs/<新工作流>/.gitkeep`
3. 在本节登记（清单一行；窗口同时开的，「现在谁在接」也加一行）
4. 在项目入口文件（`CLAUDE.md` / `AGENTS.md` …）的醒来步骤里列上它
5. DECISIONS 记一条：为什么开新工作流，而不是并进已有的一条
6. 单独 commit："**add workstream: <新工作流>**"

**结束一条工作流**：把它的 STATUS / HANDOFF 归档进 `handoffs/<工作流>/`，清单里那行标「已结束 <日期>」，删掉「现在谁在接」里那行，从入口文件的醒来步骤里拿掉，DECISIONS 记一条。名字不再复用。

### 现在谁在接（v2.8，仅几个窗口同时开时填）

> 只在几个窗口同时干活时填。工作流不变，窗口会换 —— 窗口名**只**在这张表里是当前有效的。详见 METHODOLOGY §3.6。

| 工作流 | 现在的窗口（其他窗口用这个名字找它） | 从哪天起 |
|---|---|---|
| ⚠️ TODO ⚠️ | ⚠️ TODO ⚠️ | ⚠️ TODO ⚠️ |

- **新窗口在用户确认醒来回报之后**：把自己那条工作流这一行改成自己的窗口名和日期 —— 只改这一格，单独提交，并在回复里说一声。临时窗口不认领。
- **醒来时顺手看一眼别的工作流的 STATUS**「交给别的工作流的」：有交给自己这条、还是「已发」的，就是还没人接的活。
- **要找别的工作流**：先看这张表；那个窗口已经关了 → 找名字里带这条工作流的在线窗口；还找不到 → 写进自己 STATUS 的「交给别的工作流的」，它下一个窗口醒来时会看到。
- **STATUS / HANDOFF / DECISIONS 里写工作流名，不写窗口名。**记出处可以（「web-5 发现的」），当收件人不行（「告诉 web-5」）。
- **临时窗口**（一次性的活、不归哪条工作流）不进这张表。

**接口依赖与该告诉谁**（长期有效的事实 —— 改这些、或上线这些之前，先告诉列出的那条工作流）：
- ⚠️ TODO ⚠️（例如「App 依赖网页的 `.topbar` 类名和 `/g/<id>` 链接」·「每次部署 → 前后都告诉 App」）

**同时开窗的共用规矩**（一个工作目录、几个窗口 —— METHODOLOGY §3.6.4）：
- 暂存区是共用的：每次提交前先 `git diff --cached --stat`；按文件名暂存，不用 `-A` / `-a` / `.`
- 只提交自己的改动；同一个文件里混着别的窗口没提交的改动时，只暂存自己那部分
- 共用的项目脑（MAP / DECISIONS / PROJECT）：先重读，再只改自己那一处 —— 不整份重写
- 要改别的工作流管的、或共用的范围 → 先跟它说一声（文件 + 要改什么）
- 部署从提交打包，不从工作区；部署前后都告诉受影响的工作流

## 7. MAP 自我校准

> MAP 最大的敌人是陈旧。这份文件必须有主动维护机制。

**触发更新的场景**：
- 模块新增 / 删除 / 状态变化 → 更新第 2 节（模块清单）
- 模块**大的结构变化**（重构、引入新子系统）→ 更新第 2、3 节
- 新文档加入 / 删除 / 大改 → 更新第 5 节
- 启动命令变化 → 更新第 1 节（快速开始）

**MAP 校准扫描**（不自动跑，由用户触发或 AI 主动提议）：
- 扫描 `brain/topics/`：发现文件存在但 MAP 第 5 节里未登记 → 报告"未登记文件"
- 扫描 MAP 登记项：发现登记了但文件不存在 → 报告"失效条目"
- 发现 MAP 条目描述和实际内容明显不符 → 报告"条目漂移"
- **触发时机**：
  - 用户说"MAP 校准 / 整理项目记忆"时
  - 完成某个大的模块改动之后（AI 主动提议跑校准）
